A small playbook for a task you repeat.

A skill gives an AI assistant a reusable method: when to help, what to do, what a useful result looks like, and what to check. It can include examples or reference files. You can inspect and edit the instructions yourself.

Skills help when you keep repeating the same directions. Save your preferred editing process once, for example, and use it with your next draft. The assistant can recognize relevant tasks from the skill’s description, or you can ask for the skill by name.

The common format is a folder with a SKILL.md file. Both platforms support this open approach; setup and available tools depend on the product you use. See the Agent Skills specification, OpenAI’s skill guide, and Claude’s skill guide.

From a request to a reusable method

A prompt: “Help me choose a desk.”

A skill: “Compare my options against my budget and priorities. Separate facts from unknowns. Explain what would change the recommendation.”

Your next request: “Use Compare Options for these two desks. My budget is $80.”

The skill supplies the method. Your request supplies the current task.

Download. Install. Try a real task.

Start with one skill you need today. Inspect its instructions before installing. A skill provides a workflow; it does not switch on browsing, create an account, or add tools your assistant does not have.

Claude

  1. Download one skill ZIP.
  2. Open Customize → Skills. Choose + Create skill → Upload a skill.
  3. Select the ZIP and enable the skill. Account or organization settings may affect availability.
  4. Start a conversation, ask Claude to use the skill by name, and try its example request.

ChatGPT

  1. Download one ZIP. Keep its skill folder intact.
  2. In a workspace that offers uploaded skills, use its Skills → Create → Upload flow. Select one ZIP, then enable it.
  3. In the ChatGPT desktop app, open Skills. You can also ask the built-in skill creator to create a skill from the instructions in the download.
  4. Select the installed skill or ask for it by name, then try its example. Workspace permissions and product surfaces differ.

My tool does not offer skill installation. Can I still try the workflow?

Open a starter’s instructions and paste the workflow into a conversation with your task. This lets you try the method as a prompt. It does not install the skill or make it available automatically in future conversations.

Check that it helps.

Try the same request with and without the skill. Compare the results against the checks in its eval.md. Look for an observable improvement: a supported citation, an unchanged factual claim, a usable file, or a question that gives you a chance to practice. Confirm that the assistant loaded the skill instead of assuming it did.

The downloads have been checked for folder structure, required metadata, and matching package contents. The included practice tests are yours to run in ChatGPT and Claude; they are not a claim of completed testing in either account.

Make a skill that travels.

Keep the core instructions in plain language and the shared folder format. Add platform-specific integrations only when the task requires them.

  1. Choose one repeatable job. Name the input and what a useful result looks like. “Turn meeting notes into actions” is easier to test than “Be my productivity expert.”
  2. Write a clear trigger. The name and description help the assistant decide when to load the skill. Explain when it belongs and any important boundary.
  3. Describe the decisions that matter. Include the workflow, output, missing-information policy, and checks. Keep current prices, standards, and facts in references that can be verified.
  4. Keep tools flexible. Say “use available browsing tools” rather than requiring one vendor’s tool name. If the tool is missing, explain what can still be done.
  5. Package one skill per ZIP. Use a lowercase hyphenated folder name that matches the frontmatter name. Put that folder at the ZIP root.
  6. Test in both hosts. Try a normal task, a missing-input or missing-tool case, and a request where the skill should stay out of the way. Refine based on the results.

Use one folder with a matching lowercase-hyphenated name and a SKILL.md containing name and description frontmatter. Keep the core instructions independent of a platform's tool names. Explain what to do if required inputs or tools are missing. Add an eval.md with a normal task, an edge case, and a request that should not trigger the skill. Show me the instructions and create a ZIP if file tools are available. Do not claim tests you did not run.

A shared format makes a skill portable. Results can still differ because models, tools, permissions, and interfaces differ. Keep the workflow the same and test the behavior in each place you use it.
