Prompt Library

              
Copy these into Codex when you need a narrower task.

            

          

          
# Inspect First
Inspect this project and summarize what it does. Do not edit files yet. Identify the important files, how to run it, and the safest first improvement.

# New Feature
Add this feature using the existing project style. Make the smallest working version first. Do not add dependencies unless necessary. After editing, give me click-by-click test steps.

# Bug Fix
Find the root cause of this bug. Fix it with the smallest safe change. Do not rewrite unrelated files. Explain how to verify the fix manually.

# Cleanup
This project has become confusing. Inspect the files, identify duplicate or unused code, and suggest a cleanup plan in small steps. Do not change behavior unless I approve it.

# Pre-Publish Check
Check that this project opens correctly, has no missing files, works on mobile and desktop, protects privacy, and has clear instructions. Do not add new features.

How This Helps

              
The goal is to give Codex better context before coding starts.

            

          

          
This website turns a vague project idea into a structured Markdown brief. Non-coders can use it to explain goals, users, features, privacy limits, and workflow rules before asking Codex to inspect or change files.

          
The recommended workflow is: Define → Inspect → Plan → Build Small → Test → Report. This prevents large accidental rewrites and makes it easier to understand what changed.

          
Best first instruction for Codex: “Start by inspecting the project. Do not edit files yet.”
